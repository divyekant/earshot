Retry policy

When a job fails, Tessel can run it again. The retry policy of a queue controls how many times a job runs again and how long Tessel waits between two attempts.

By default a job gets 5 attempts. The wait time starts at 10 seconds and doubles after each failed attempt, up to a limit of 15 minutes.

Set the policy for a queue

Put a retry block in the queue section of tessel.toml:

[queues.email]
retry.max_attempts = 8
retry.first_wait = "30s"
retry.factor = 2.0
retry.max_wait = "1h"
retry.jitter = true

With these values, the waits are 30 seconds, 1 minute, 2 minutes, and so on. After the eighth failed attempt, Tessel moves the job to the dead letter queue.

Options

OptionDefaultMeaning
max_attempts5The total number of attempts, with the first run included.
first_wait10sThe wait before the second attempt.
factor2.0Tessel multiplies the wait by this number after each failure.
max_wait15mThe longest wait between two attempts.
jitterfalseIf true, Tessel changes each wait by a random amount of up to 20 percent, so that many failed jobs do not start again at the same moment.

Errors that must not retry

Some errors do not go away. A retry of a job with a wrong address is a waste. Raise tessel.Permanent in the job, and Tessel moves the job to the dead letter queue at once:

from tessel import job, Permanent

@job(queue="email")
def send_receipt(order_id):
    order = load(order_id)
    if not order.email:
        raise Permanent("order has no address")
    deliver(order)
Note: A timeout counts as a failed attempt. If a job is stopped because the worker shuts down, the attempt does not count.
